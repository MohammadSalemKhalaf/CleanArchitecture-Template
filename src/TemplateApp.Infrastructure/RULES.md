# Rules: TemplateApp.Infrastructure

Read [../../RULES.md](../../RULES.md) first.

## Responsibility

Implementations of the interfaces Application defines, plus technical concerns:
- EF Core with SQL Server, entity configurations, migrations and the audit interceptor;
- database initialisation;
- the HybridCache/Redis cache provider;
- health checks for its dependencies;
- option classes.

## Dependencies

| Allowed | Forbidden |
|---|---|
| Application, Domain, EF Core SQL Server, HybridCache, StackExchange.Redis, `Microsoft.Extensions.*` | Api, Contracts, ASP.NET Core (`Microsoft.AspNetCore.*`) |

Enforced by `LayerDependencyTests.Infrastructure_DoesNotDependOnTheApiOrContracts`.

## Code placement

```
Data/
  AppDbContext.cs                        implements IAppDbContext; translates unique-index violations
  ApplicationDbContextInitialiser.cs     MigrateAsync, SeedAsync, InitialiseDatabaseAsync (config-gated)
  Configurations/<Entity>Configuration.cs
  Interceptors/AuditableEntityInterceptor.cs
  Migrations/                            generated by dotnet ef, never edited by hand except to fix generated SQL
Caching/                                 HybridCacheService (ICacheService), tag index, Redis health check
Settings/                                option classes bound from configuration (CachingOptions, DatabaseOptions)
ConnectionStringNames.cs, HealthCheckTags.cs
DependencyInjection.cs                   AddInfrastructure(IConfiguration)
```

## Conventions

- **Entity configuration:** one `IEntityTypeConfiguration<T>` per entity, discovered by `ApplyConfigurationsFromAssembly`. Use the entity's constants for lengths. Declare unique and lookup indexes here.
- **Migrations:** every model change needs a migration (`Migrations_MatchTheCurrentModel` fails otherwise). Keep migrations backward compatible (expand, then contract), because rollbacks never revert the schema.
- **Startup initialisation:** only through `Database:InitializeOnStartup`/`Database:SeedSampleData` (Development). Deployments run `--migrate` once.
- **Sample data** in `SeedAsync` belongs to the example feature; replace it with your own or remove it.
- **Implementations** are `internal sealed` unless the Api or tests must construct them, and are registered in `DependencyInjection.cs` only.
- **Caching must fail open:**
  - cache errors are logged as warnings and the factory result is returned;
  - factory errors propagate.

  Keep Redis optional: an empty `ConnectionStrings:Redis` means in-process cache only.
- **Health checks:** register every external dependency under `HealthCheckTags.Ready`. A dependency the API can work without (Redis) reports `Degraded`, not `Unhealthy`.
- **Configuration:** bind option classes from a named section, and validate required values with `ValidateOnStart`.
- **No business rules here.** If an `if` depends on a business concept, it belongs in Domain or Application.

## Testing

`tests/TemplateApp.Infrastructure.IntegrationTests`, against real SQL Server and Redis containers (Testcontainers):
- migrations match the model;
- interceptors stamp audit data;
- database constraints are translated;
- cache hit, miss and invalidation;
- fail-open behaviour;
- cross-instance invalidation.
